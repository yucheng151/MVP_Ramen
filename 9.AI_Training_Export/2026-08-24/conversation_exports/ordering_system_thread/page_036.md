### 使用者

### AI（final_answer）

對，PLC內部應該有一個FIFO訂單區。HMI把每一碗送進PLC，PLC依照先進先出製作；完成後再依序回覆對應的`Unit ID`。

要注意：PLC儲存的不是整筆客戶訂單，而是「每一碗的製作單位」。

例如：

```text
訂單A：3碗 → Unit 1001、1002、1003
訂單B：2碗 → Unit 1004、1005

PLC FIFO：
1001 → 1002 → 1003 → 1004 → 1005
```

PLC依序回報：

```text
完成1001
完成1002
完成1003 → HMI判斷訂單A完成，通知客人
完成1004
完成1005 → HMI判斷訂單B完成，通知客人
```

## PLC FIFO區域

建議使用環形FIFO，容量可以先規劃32碗或64碗：

```text
FIFO_Head       最早進入、尚未完成回覆的位置
FIFO_Tail       下一筆要寫入的位置
FIFO_Count      PLC目前保存的Unit數量
FIFO_Capacity   FIFO容量
Cook_Pointer    下一份要開始煮的Unit
Bowl_Pointer    下一個要落碗的Unit
```

每一筆Unit建議保存：

| 欄位 | 用途 |
|---|---|
| `Unit_ID` | 這一碗的唯一編號 |
| `Recipe_No` | 食譜編號 |
| `Noodle_Cabinet_No` | 麵櫃格號1～10 |
| `Job_State` | 等待／製作中／完成待回覆 |
| `Noodle_State` | 等煮／煮麵中／煮好／Standby／已入碗 |
| `Bowl_State` | 等落碗／輸送中／X0.2／X0.3／X0.4／出料 |
| `Cooker_No` | 使用煮麵位置1～3 |
| `Flags` | UR1、UR2、倒麵、加湯完成旗標 |

麵與碗會同時進行，因此不能只用一個狀態。必須分成`Noodle_State`與`Bowl_State`。

## PLC接收Unit流程

```text
HMI送出CMD 70＋Unit ID
→ PLC檢查FIFO是否有空位
→ 檢查Unit ID是否重複
→ 寫入FIFO Tail
→ FIFO Tail往下一格
→ FIFO Count加1
→ 回覆HMI接收成功
```

如果FIFO已滿：

```text
PLC回覆FIFO Full
→ HMI保留該Unit
→ 等PLC有空位後重新送出
```

## PLC製作排程

```text
FIFO有等待中的Unit
→ 煮麵位置有空位
→ 確認UR1與UR2都沒有動
→ 取最前面的待煮Unit
→ 綁定煮麵位置1、2或3
→ 啟動煮麵
```

落碗也依照FIFO順序：

```text
取最前面的待落碗Unit
→ CMD 103預先影像辨識
→ 執行落碗
→ X0.1確認
→ 碗綁定Unit ID
```

即使後面的麵先煮好，也只能先進入等待或Standby，不能倒進前一碗，必須依`Unit ID`配對。

## 完成回覆FIFO

當一碗完成加湯並離開`X0.4`：

```text
該Unit的Bowl State = 已出料
該Unit的Job State = 完成待回覆
```

PLC檢查FIFO Head：

```text
FIFO Head是否完成？
→ 是：將Head的Unit ID回覆HMI
→ 等待HMI回覆ACK
→ 清除這筆Unit
→ FIFO Head往下一格
→ FIFO Count減1
→ 再檢查下一筆
```

PLC必須等HMI確認收到，才可以清除Unit：

```text
PLC → HMI：
Complete Valid
Complete Event Index
Complete Unit ID

HMI → PLC：
Complete ACK Index
```

如果HMI斷線，PLC保留完成的Unit ID，不可以直接清除，等HMI重新連線後繼續回報。

## 建議的PLC內部結構

可先規劃一個尚未使用的D區域，例如：

```text
FIFO控制區
D1500  FIFO Head
D1501  FIFO Tail
D1502  FIFO Count
D1503  FIFO Capacity
D1504  Cook Pointer
D1505  Bowl Pointer

FIFO資料區
D1520開始
每一筆Unit使用10個WORD
共32筆＝320個WORD
```

這只是建議位址，正式使用前仍要確認PLC現有D區沒有占用。

最終分工就是：

```text
HMI：
保存不限量客戶訂單
逐碗產生Unit ID
FIFO有空位就送給PLC
收到完成Unit ID後更新客戶訂單

PLC：
保存固定容量的Unit FIFO
依FIFO順序煮麵、落碗及出料
完成後依FIFO Head順序回覆Unit ID
收到HMI ACK後才刪除該筆Unit
```

這樣即使三個煮麵位置同時工作、多個碗在輸送帶上，訂單順序與客人通知仍然不會混亂。

同一次停止可能同時處理多個碗，例如：

- `X0.3`有碗：UR2動作

```text

X0.3完成 = UR2完成
X0.4完成 = 加湯完成
```
