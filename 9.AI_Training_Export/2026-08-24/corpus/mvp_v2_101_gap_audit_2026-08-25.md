# MVP V2_101 缺口查核報告（2026-08-25）

## 結論摘要

本次以工作區原始碼、測試紀錄、MVP_V2_101 ISPSoft 列印 PDF 與專案檔雜湊交叉查核。PDF 內容只作為證據，不視為操作指令。

1. D1024、D1132、D1134 已在 V2_101 實作，並已補入 `3.HMI/0.0.3/auto_plc_contract.py`。
2. 10 碗狀態、10 個麵櫃數量、2 個空盒櫃仍沒有可確認的正式 PLC 位址，不應猜測。
3. 工作區 V2_101 專案本身可識別，但沒有 PLC 線上比對、下載紀錄或現場 checksum，不能宣稱它就是機台實際運轉版。
4. `REGISTER_MAPPING_PENDING.md` 所列 Process／Recipe 欄位仍沒有一對一的正式地址。現有 D1000 命令、D1014 SemiAuto StepMask 與 D1102/D1103 ACK/Response 是既有通道，不等於整批新欄位已完成。
5. V2_101 已確認使用台達 TMR 與 MODRWE 實際接線模式；細節已補入語法除錯資料。
6. IPC 0.0.2 是工作區中最完整的雙 UR5e 整合候選，但沒有部署紀錄，不能標為現場正式版。
7. UR5e 已有 RTDE／Robotiq／PLC bridge 程式層整合；Nachi 主要是 PLC 握手與控制器程式，未見 Python Nachi vendor SDK。硬體投產狀態均待現場證據。

## 1. 訂單契約

V2_101 的 `HMItoPLC_Order` 變數表明確列出：

| 名稱 | 位址 | 型別 | 用途 |
|---|---:|---|---|
| HMItoPLC_UnitID | D1020 | DINT | 訂單 UnitID |
| HMItoPLC_UnitCabinetNo | D1022 | INT | 麵櫃 |
| HMItoPLC_UnitFirmnessNo | D1023 | INT | 軟硬度 |
| HMItoPLC_OrderIndex | D1024 | WORD | 訂單序號 |
| HMItoPLC_OrderValid | D1025 | WORD | 1 表示有效 |
| PLCtoHMI_OrderAckUnitID | D1130 | DINT | ACK UnitID |
| PLCtoHMI_OrderAckIndex | D1132 | WORD | ACK Index |
| PLCtoHMI_OrderFIFOCount | D1133 | INT | FIFO 數量 |
| PLCtoHMI_OrderResponseCode | D1134 | INT | 200 成功；400 以上拒絕 |

同頁程式可見初始化、通訊異常 901、Index 去重、先保存 ACK 資料，再進行 UnitID、參數與 FIFO 驗證的流程。因此這三個缺欄位不是測試自行假設。

## 2. 尚未配置的資料區塊

V2_101 的列印資料可看到三個麵篩與四站 debug/monitor 訊號，但沒有找到下列完整交換區塊：

- 10 筆 UnitID＋狀態的 HMI 正式資料區。
- 10 個麵櫃的雙向庫存資料區。
- 2 個空盒櫃的雙向數量資料區。

因此 `address=None` 應保留，直到 PLC 端新增並通過地址重疊檢查、編譯與握手測試。

## 3. 版本身分與實機狀態

工作區 `MVP_V2_101.isp` 與 `.bak` 的 SHA-256 相同：

`4EEDE860F61B9D18A6E1098719967471ED1BDA3974D374EDD335F93D77D1566F`

這只能證明工作區兩檔內容一致。現有舊驗證報告明確記載當時 Simulator 跑的是 V2_100；1000 筆測試證明訂單管線耐久，但 log 沒記錄 PLC 專案 checksum。要確認現場版本，仍需 ISPSoft Online/Offline Compare 或 PLC 下載／維護紀錄。

## 4. Process／SemiAuto／Recipe 映射

已確認的既有訊號包括 D1000 命令碼、D1001 命令 Index、D1002 Valid、D1014 SemiAuto StepMask、D1102 ACK Index 與 D1103 Response。這些可以作為未來設計基礎，但目前沒有證據能將 `Current_Process_Step`、Alarm source/detail、Recipe Index/Version、參數 Accept/Reject 等逐一正式映射，因此 pending 文件維持有效。

## 5. 語法與除錯

- TMR：梯圖使用 TIMER 變數作 S1、時間設定作 S2；ST 中存在 `TMR(timer, preset)` 寫法。
- MODRWE：V2_101 梯圖已提供多組 S1/S2/S3/S4/S/n 實例與 M100 完成握手，可照既有模式複製，再以同版 ISPSoft 編譯確認。
- 不應從畫面數值單獨推導所有 MODRWE 端子的通用語意；跨設備／功能碼修改仍需指令手冊。

## 6. IPC 與 Robot 整合成熟度

`6.IPC/0.0.1/ipc_controller.py` 的 SmallMaterialRobot 是 placeholder。`6.IPC/0.0.2/isaac_dual_food_ur5e_2bowls1.py` 則已有 Isaac Sim、ROS2、RTDE、Robotiq、雙控制器隔離檢查、PLC 101/102/103 bridge 與復原邏輯，故 0.0.2 應標為「主要整合候選」。缺少現場啟動服務、部署清單與硬體成功 log，所以不能標為 verified production。

Nachi 端在 PLC 中已有 Robot Exchange、D12100～D12156 握手與全自動仲裁，但工作區未見 Python Nachi vendor SDK。這代表 PLC 層整合存在，SDK 層與現場 commissioning 狀態仍待補證據。
